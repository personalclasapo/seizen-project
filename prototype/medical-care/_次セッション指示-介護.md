## 決めたこと（ユーザー確認済み・2026-09-09）

### 1. 上部を薄くする

- 介護認定（`.cp-level` プレート）と担当者・相談先（`.cp-manager`
  プレート）を**プレートから降ろす**。地の上に直接、1行の帯として置く。
- 左：`要介護2 ⓘ`。ⓘ は「要介護度とは何か」の説明への入口。
  いまの `.cl-card`（20px の大きな札）はやめる。
- 右：`介護の主な相談先`。**名前・電話は残す。Web(URL) を追加する。**
  - `care.manager.web` を state に足す。編集＝入力欄／表示＝
    `<a target=_blank rel=noopener>`。医療の `clinics.web` /
    pharmacy `web` と同じ扱い。
- **ケアマネの状態バッジ（`stBadge('care.manager')`）は落とす。**
  名前と電話を書いた時点で家族は辿れるので §11 の状態を問う対象では
  ない。医療の通院カード・薬局から撤去したのと同じ理由。
  `careRows()` の数え上げからも manager を外す。

### 2. 今の支援 ── 2節に割る

いまの4列の表（`.svtbl` / `.svr`）は、性質の違う2つを1つの表に
混ぜている。訪問・デイ・配食は**曜日と時間**を持ち、ベッド・歩行器・
見守り機器は**ずっと家にある**。割る。

#### 2-a. 暮らしの時間に入る支援 ＝ 卸しカレンダーの1週分

**造形**：卓上の週間ブロックカレンダー。月〜日のマスに、その日に
入る支援のグリフが乗る。リング・ミシン目・紙の地を SVG で。

**★曜日は「管理するもの」ではない（ユーザー明言）。**
「本当に曜日ごとに管理したいというより、デザインとしての描写目的」。

- **`DAYS` / `weekGrid` / `hasSchedule` / `toggleDay` は復活させない。**
  今朝の削除は正しかった。曜日トグルの入力UIは作らない。
- 編集対象は今まで通り `use` の自由文（「月・木 午前（9:00〜12:00頃）」）
  だけ。そこから曜日を**読み取って**マスに点を打つ。
- 曜日は状態ではないので §11 の対象外。`careTally()` に入れない。
- **読み取れなかったときは何も打たない。**「毎日 夕方」「週1回（火）」
  など書き方が揺れるので、拾えない行は帯を薄いままにする。
  推測で打つと、家族が書いた文字と絵が食い違う ── これは避ける。

#### 2-b. 継続して使っている支援 ＝ 物そのものを並べる

**造形**：ベッド・歩行器・見守り機器の絵を、小さな絵札として横に
並べる。「家にこれがある」が直に分かる形。

- データの持ち方は造形に合わせる。いまの `services` の
  `kind:'equip'` 系を割るか、`care.equipment` を別に立てるかは
  **造形を決めてから**（ユーザー指示）。
- 事業所・連絡先は持つ（福祉用具は貸与元に連絡することがある）。

### 3. 介護で使う大事なもの ＝ クリアポケット

- 節名を「介護関係の書類やもの」→ **「介護で使う大事なもの」**。
- **いまの荷札は捨てる。** `ctagShape()` / `CTAG_SHAPE` / `.ctag` 系
  CSS を削除。荷札は「物に結ばれている札」であって、書類を収める器
  ではない。ユーザー判断（2026-09-09）。
- 造形は**クリアポケットのファイル**。透明ポケットが横に並び、書類の
  頭が少しのぞく。中身の名前と所在が読める。
- **「数値だけの調整じゃなくて、モチーフを持ってこれるなら持ってきて」**
  （ユーザー明言）＝ CLAUDE.md の振り分けで「素材を探すのが先」の側。
  着手前に CC0 を探し、採否と理由を RESEARCH.md に残す。
- 持つのは名前＋所在だけ（§13-1）。中身（保険証の番号など）は持たない。

## 素材の方針

**CC0 のみ**（2026-09-09 確定・`care-board-motifs.RESEARCH.md` §3）。
CC BY-SA（OpenMoji 等）は share-alike を持ち込まないので不採用。

素材を探す対象（「それらしさ」に説得力が要る）：

| 対象 | 状況 |
|---|---|
| クリアポケットのファイル | 未探索。Openclipart から当たる |
| ベッド（介護ベッド） | 未探索 |
| 歩行器 | 未探索 |
| 見守り機器 | 未探索。抽象度が高いので自作に落ちる可能性 |

**曜日の帯について**：CC0 のカレンダー素材を当たったが、Openclipart
にあるのは「壁掛けの月間カレンダー」（数字が並ぶ月表）で、**週の帯とは
別の物**だった。卸しカレンダーの1週分は、リング＋紙＋ミシン目の
幾何プリミティブで成立する側なので**自作可**。ただし
`svg-motif-source-first` のとおり、スクショ→座標を2回動かしたら
手を止めて素材探しに切り替える。

## ★素材の判定基準（ユーザー明言・2026-09-09）

> 「木かどうかが問題なのではなく、**自作でのクオリティの低さ**が要因。
> クオリティを確保できるのであれば、全体で違和感がないモチーフで
> あれば問題ない。」

CLAUDE.md の「PD/CC0 素材を探すのが先」を**無条件の門と読むのは誤り**。
規則自身が理由を「破綻した自作を置くより」と書いており、判定基準は
出どころではなく**結果の質**。素材探しは手段であって目的ではない。

検出器は CLAUDE.md §2 のほう ──「スクショを見て座標・px を1つずつ
動かす作業を2回以上やったら手を止める」。ここに入ったら素材へ切り替える。

### 完了：「介護関係の書類やもの」＝ 画鋲で留めたメモ紙へ作り替え（2026-09-12）

**★2026-09-11 の「荷札のまま描き直す」方針は、この回でさらに覆った。**
荷札（`ctagShape` / `ctagShapeHung` / `papersBar`、`?papers=bar`/`tag`
の2案）は全て削除し、**画鋲で留めたメモ紙**（`memoPaper()` / `CMEMO_PIN`）
に作り替えた。経緯と最終形は次のとおり。

#### 何が起きていたか

9/11 の「荷札のまま3点を直す」方針で `?papers=bar`（桟から吊る）と
`?papers=tag`（札単体の作り込み）の2案を実装したが、実際に並べて
見ると、どちらも札が板の上に**ただ置かれている**ままで、上2節
（カレンダー＝リングで綴じる、棚＝受けで支える）が持つ「その物が
現実でどう留まっているか」を最後まで持てなかった。'bar' 案は桟の
ほうが目立ち、札が桟に添える飾りに見えた。

ユーザーが「画鋲で留めたメモ紙」の参考画像2点を提示。介護ゾーンの
器はコルクボード＝掲示板の比喩（額縁＋背板＋ネジ）なので、画鋲は
**この器が現実に持っている留め方**そのもの。荷札が「宙に浮いて
見える」という 9/11 からの積み残しの問題（結び先が無い）が、画鋲なら
留め先が背板になるので構造として解けると判断し、モチーフごと
差し替えた。

★参考画像は仕様書ではなく構造のヒント（§追補2 の教訓）。取ったのは
「画鋲で留まる／紙が複数重なる／紙がたわむ」の3点で、参考画像の
写実的なぼかし影・太い黒縁は持ち込んでいない。SeiZen の塗り＋細い線
に寄せた。

#### 実装の要点

- **紙は2枚重ね**（`memoPaper()`）。裏の紙は表と逆向きにわずかに
  傾けてずらし、角を外へ出す――真下に隠すと影と見分けがつかず層が
  潰れる（1回目の実装で実際に潰れた。§8 と同じ教訓）。
- **紙の上辺は「画鋲で留めた中央が高く、両端が垂れる」向き**に反らせる。
  逆（中央が膨らむ）だと紙が下から押されているように見えて画鋲と
  噛み合わない（1回目の実装がそうなっていて、直した）。
- **画鋲**（`CMEMO_PIN`）は頭（球）＋針の根元＋紙に落ちる影の3層。
  影は頭の横ではなく紙の面（頭より下）に落とす――頭の横に置くと
  板の上に転がって見える。色は介護ゾーンの緑系に統一（赤・青は
  ボードの色数を増やすので避けた）。
- **item のアイコンは維持**（`CARE_DOC_IC`）。所在（`PIN_MARK`）・
  状態バッジも荷札のときから変更なし（§11/§12・決着済み事項は
  下記のとおり据え置き）。

#### レイアウト：4列グリッド → container query で 2列・1列

ユーザー提案の「4列」を採用。紙はほぼ同じ大きさの小片なので、
幅なりに折り返す flex ではなく `grid` で列を揃えた。列数は
ビューポート幅ではなく**器の実幅**（`.cp-papers .cp-body` に
`container-type:inline-size`）から決める――介護ボードは左の
サイドバーぶんビューポートより狭く、幅ごとに畳まれ方が変わるので
`@media` では合わない（カレンダー行と同じ事情）。

★`.cmemos` 自身に `container-type` を付けても要素は自分自身を
問い合わせられずクエリが一度も効かない、と実測で判明。container は
**親**（`.cp-body`）に置くこと。

実測（器の実幅）：

| 幅 | 器の実幅 | 4列時の1枚幅 | 列数 |
|---|---|---|---|
| 1400/1000 | 784/754px | 176〜184px | 4列（成立） |
| 780/620 | 476/495px | 107〜113px | 2列（4列だと短冊に潰れる） |
| 400 | 244px | ― | 1列 |

傾きなしで統一後、紙の高さは全幅で108pxに揃う（横スクロール無し・
JSエラー0、CDP で編集モード・「＋足す」も確認済み）。

#### 見た目の仕上げ（ユーザー確認の実機フィードバックで3往復）

1. **傾きは撤去。** 紙ごとに角度を変える案（`--tilt`、±0.9°）を
   最初に入れたが、ユーザー指摘「まず傾きの名残がある。この場合は
   傾き不要」。4列グリッドの上では傾きが「散らかった名残」にしか
   見えず、留め物らしさには画鋲と紙の層で足りていた。
2. **紙をほぼ白まで明度アップ。** 当初の地色（`#fffdf8〜#f0e6d6`）は
   プレート地（`#f7f1e9〜#eae0d3`）とほぼ同レンジで、ユーザー指摘
   「白要素増やして良い。背景との差がない」。`#ffffff〜#f5f3ee` に
   上げてコントラストを付けた。裏の紙は真っ白にすると表との層が
   消えるので、薄いベージュ（`#e4d9c4`）を残す。
3. **末尾の注記文「原本の場所は『書類・資料』にまとめています。」を
   削除。** ユーザー指摘で撤去。
4. **額の隅のネジと、紙の角／見出しアイコン／鉛筆の間隔が詰まって
   見える指摘。** 実測で突き合わせ：
   - 紙の角とネジ：左右とも隙間0〜2px相当 → `.cp-papers .cp-body`
     に左右 `padding:10px` を追加（実測8pxの隙間を確保）。
   - 見出しアイコン・鉛筆とネジ：実測で2px食い込み（アイコン
     26px・鉛筆28px 自体の大きさが `.cp` パディングの残りを
     食いつぶしていた）→ `.cp-h` に `margin:0 6px 12px`
     （実測4pxの隙間を確保）。
   - **`.cp-h` の修正は `carePlate` 全体に効く共通クラス**
     （介護ゾーン専用、医療など他領域には無い）。見出し付き
     `carePlate` は現状 `cp-papers` のみなので他プレートへの影響は
     実質無いが、次に見出し付きプレートを足すときはこの間隔が
     基準になる。

今度は色。「背板をもっと薄く」「カレンダーヘッダーは薄い緑」
「介護で使うもののアイコンも同じ薄い緑にして四角で囲む」「上部の
木札プレートも白に近い色に」という4点の指示。

★途中の誤り：カレンダーヘッダーの色として、まず SeiZen のアプリ
基調色である濃い緑（`--gr:#1E5A3D`）を提案したが却下された
（「緑ではない」）。理由を掘り下げると、濃い緑は「操作・編集」を
示すUIの色なので、木・紙・真鍮でできた物の中に置くとUI部品に
見えてしまう（CLAUDE.mdの「造形は現実の対象を連想させる」に反する）。
彩度を落とした薄い緑（`#8fae89`〜`#7a9975`）に変えて解決。

★もう1つの誤り：「木札プレートは独自の木目（CWS_GRAIN）を持つ」と
コード上の事実をそのまま述べたが、ユーザーに実際のスクリーンショット
で「これのどこが木に見えるの」と指摘され、木目は opacity が低すぎて
実際にはほぼ知覚できず、見た目としてはただの単色の面だったと判明。
★教訓：コードに実装があることと、それが実際に視認できることは別。
見た目の変更を議論するときは、コードではなく実際のレンダリング結果
（スクリーンショット）を基準にする。

実装：
- **背板**（`cbfBoard` グラデーション）：`#9a6537`系の濃い茶 →
  `#d9bb98`〜`#dec29f` の薄い色へ。
- **カレンダーヘッダー帯**（`wcalBand` グラデーション）と対の時計
  チップ（`.wcal-lead-ic`）：茶（`#7d6a45`→`#6a5936`）→ 薄い緑
  （`#8fae89`→`#7a9975`）。
- **「介護で使うもの」見出しアイコン**（`.eqs-lead-ic`）：同じ薄い緑へ
  （カレンダーの時計チップと揃える）。
- **用具アイコン本体**（`EQUIP_IC` が使う `EQ_L`/`EQ_B`/`EQ_M`/`EQ_F`
  トークン、`.c-equip` の `--sc`/`--sc-bg`）：茶系 → 緑系
  （`EQ_L:#6b8f66` など）。線・地・中間・弱線という層の役割は変えず、
  色相だけ差し替えた。
- **「介護で使うもの」を四角で囲む**：★最初はアイコン自体
  （`.eqs-obj`）に枠線＋薄い背景を付けたが、ユーザーに「アイコンでは
  なく、台（棚板）と文章の部分」と訂正された。棚板が箱の蓋を兼ね、
  その下に文章（`.eqs-cap`）だけを枠で囲む形に直した
  （`border-top:0` で棚板と地続きにする）。アイコン自体
  （`.eqs-obj`）は枠を撤去し元の見た目に戻した。
- **「介護で使うもの」の列を「介護関係の書類やもの」と揃える**：
  `.eqshelf` を `flex;flex-wrap:wrap`（札は固定172px）から、
  `.cmemos` と同じ `grid-template-columns:repeat(4,1fr)`
  ＋同じ container query の閾値（600px→2列、300px→1列）へ作り替え。
  `.cp-equip .cp-body` にも `.cp-papers .cp-body` と同じ
  `container-type:inline-size` を追加。
- **木札プレート**（`careWoodSlat` の `cwsWood` グラデーション、
  `.cws-plane` の彫り面）：茶系 → 白に近いオフホワイト
  （`#fbf9f4`〜`#ede7d9`系）。木目（CWS_GRAIN）はそのまま残すが、
  この面は木として知覚されていなかったので、木目の扱いは気にせず
  地の色だけ差し替えた（ユーザー確認済み：「木は枠の方でしか
  再現してない」）。
- 要目視確認：1400 幅で4点とも反映されていることをスクショで確認。
  棚のグリッド化で列数の挙動が変わったので、狭幅（600px以下・
  300px以下）での崩れも別途確認が要る。
