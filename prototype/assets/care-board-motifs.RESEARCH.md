# 介護「連絡ボード」— 造形の素材調査と実測

`介護イメージ.png`（造形の正本）から**実測した寸法・色**と、モチーフを
自作するか素材を持ってくるかの**着手前判定**（CLAUDE.md）の記録。

前回の実装は、この判定をやらずに `div` ＋ `border-radius` ＋
`linear-gradient` で器を組み、あとから座標と px を動かしていた。
正本と並べると額縁・プレート・荷札・行頭アイコンのいずれも
「何の絵か」が言えない状態だったので、器から作り直す。

## 3. 素材の探索ログ（採否と理由）

### 採用：Openclipart `kitchen-icon`（配食）

- 出どころ：https://openclipart.org/detail/169913/kitchen-icon-knife-spoon-fork
- **ライセンス：CC0（パブリックドメイン）**
- 構造：`viewBox 0 0 276.285 286.559`、`knife` / `spoon` / `fork` の
  3グループ。塗りは `#231F20` のフラット単色、**グラデーション0個・
  transform 無し**。SeiZen の視覚言語（単色フラット）とそのまま合う。
- 使うのは **fork と knife の2グループだけ**（皿は円で描くので spoon は不要）。
- 保存先：`care-cutlery.svg`

### 不採用：Wikimedia `Broom_.svg`（生活支援）

- https://commons.wikimedia.org/wiki/File:Broom_.svg
- ライセンスは CC0 で問題なし。作者 Eugenio Hansen, OFS。
- **却下理由**：実際にレンダリングして確認したところ、黒い輪郭線＋
  木目のグラデーションが入った「魔女のほうき」風の斜めの絵で、
  744×1052 の画角に対し穂先が切れている。18px の行頭アイコンに
  落とすと**斜めの棒にしか見えない**。register（単色フラット）も違う。

### 生活支援は「ほうき」をやめる

CC0 で 18px に耐えるほうきのグリフが見つからない。ここで自前の
ベジェを描き始めるのは**人体ループの入口**（`svg-motif-source-first`）。
→ **バケツ（台形＋楕円の口＋半円の取っ手）**に変更する。
家事の支援を指す物として通り、かつ台形と円弧で成立するので
「幾何プリミティブ数個」の側に落ちる。正本画像はほうきだが、
CLAUDE.md の判定（破綻した自作を置くより素材／成立する造形を選ぶ）を
画像の再現より優先した。

### 不採用：OpenMoji（🏷 荷札ほか）

揃ったグリフがあるが **CC BY-SA 4.0**（帰属表示＋派生物の share-alike）。
`medical-right-motifs.RESEARCH.md` で未解決だった分岐を、
**このプロジェクトは CC0 のみ**で確定（2026-09-09 ユーザー判断）。
既存の外部素材 `body-front.svg` も CC0 で、医療領域は外部素材なしで
出荷済み。share-alike の義務をプロトタイプに持ち込まない。

→ `_motif-candidates/` の OpenMoji / Emojione BW 各ファイルは
**採用しない**（調査の記録として残置）。

### 不採用：木のフォトテクスチャ（data URI）

当初 CC0 の木テクスチャを data URI で敷く方針だったが：

- OpenGameArt から取得した `wood_5.png` は 2400×781 / **956KB**。
  data URI にすると base64 でおよそ 1.3MB がリポジトリに載る。
- そのうえ**取得元ページと一致せず、ライセンスを確認できなかった**
  （`wood-texture-tiles` の中身は wood1.jpg / wood2.jpg のみ）。
  出どころを確定できない素材は使わない。
- 色も濃いマホガニーで、正本の**明るいオーク**（`#ce945f` 系）と別物。

→ **木目は SVG 側で描く**。ただし従来の「Δ3 の縞」ではなく、
実測の **Δ78** に合わせて、幅と濃度の違う縦筋を不等間隔で重ねる。
柾目は本来まっすぐなので、`feTurbulence` のうねりは不要。
これはテクスチャ画像の代用ではなく、**柾目という対象そのものの描写**。

## 3b. 上部の木札（2026-09-09・第3回）

介護度と主な相談先をプレートから降ろし、**1枚の木札の帯**に載せた。
プレート（乳白の樹脂板＋真鍮ネジ）より一段軽い格が要るが、
**「軽い」は「装飾なし」ではない** ── 背板に文字が直に乗ることは
実物では起きないので、物として札を留める（ユーザー指摘）。

### 判定の訂正（記録として残す）

当初「木の札は自作しない」の指示を受けて Openclipart を探したが、
**4点とも register が合わず不採用**：

| 素材 | viewBox | 却下理由 |
|---|---|---|
| [wood plank](https://openclipart.org/detail/302883/wood-plank) | 206×32 | 比率は理想的だが黒の輪郭線＋節だらけの漫画木目。塗り無しの線画 |
| [wooden sign no mask](https://openclipart.org/detail/188684/wooden-sign-no-mask) | 420×313 | 端が斧で割ったギザギザ。素朴派の看板 |
| [wooden blank sign](https://openclipart.org/detail/180885/wooden-blank-sign) | 595×310 | 鎖で吊るした看板。594KB。かすれ塗装 |
| [wood sign](https://openclipart.org/detail/91099/wood-sign) | 608×603 | 柱と草が付いた道標 |

共通の理由は**画風の不一致**（素朴・野外・輪郭線あり）。この板は
明るいオークの直線的な柾目で、輪郭線を持たない。加えて帯は幅が
620〜1400px で伸び縮みするので、輪郭が固定された1枚絵は使えない
（荷札で踏んだ「引き伸ばすと斜めが寝る」と同じ）。

**ユーザーの基準（明言）**：「木かどうかが問題ではなく、自作での
クオリティの低さが要因。クオリティを確保できるなら、全体で違和感が
なければ問題ない」。CLAUDE.md の「素材を探すのが先」を無条件の門と
読むのは誤り ── 規則自身が理由を「破綻した自作を置くより」と書いて
おり、**判定基準は出どころではなく結果の質**。検出器は §2 の
「座標を2回動かしたら止まる」のほう。

→ **額縁と同じ材から切り出す**方針にした（`careWoodSlat()`）。
同じ板なので画風は定義上ずれず、伸び縮みも額と同じ理屈で解ける。

### ハマった点：木目は「桟の筋」を流用できない

`WOOD_GRAIN`（額の桟用）をそのまま札に敷いたら、**木目が消えて
ただの色帯**になった。原因は筋幅の尺度：

- 額の桟は幅 34px。筋幅 0.5〜1.9／100 は実寸で 1px 前後 → 木目に見える
- 札は幅 900px。同じ値が実寸 5〜17px の帯に化ける → 色ムラに見える

→ 札は札の実寸で筋を持つ（`CWS_GRAIN`）。筋の太さは
`vector-effect="non-scaling-stroke"` で実 px に固定し、幅が変わっても
1px 前後を保つ。

**濃さは §1 の実測 Δ78 に合わせる。** 最初 .05〜.13（Δ5 相当）で
置いて平板になった ── これは額の桟で一度通った失敗の繰り返し。
逆に等間隔で濃く並べると今度は**ルーバー（羽板）**に見えたので、
間隔を 3〜11 で散らし、筋ごとに始点・終点を変えて途中で消えるように
した（木理は寄る所と空く所がある）。

### 直し：1行に詰めて両方読めなくなった（同日・レビュー指摘）

最初、介護度と相談先を**1行に収めた**ら、こうなった：

- 両方とも 11〜13px に潰れて読みづらい
- 右側が「介護の主な相談先 山田 花子 ○○居宅介護支援事業所 045-…
  サイト」という**切れ目のない一続きの文字列**になり、二者の区別が
  付かない
- 木目が文字の背後を横切って、さらに読みにくい

**原因**：「薄く」を**行数**の話と読んだこと。ユーザーが言っていたのは
**格**の話で、しかも「相談先との兼ね合いを検討して」と最初に
指示されていた（帯は相談先と同じ高さになるから、と）。

**直し方は3つとも「物として」解いた**（CSS の小手先にしない）：

1. **彫り込んだ平面**（`.cws-plane`）… 実物の彫り看板と同じで、字の
   下だけ木を削って平らにする。木目が字を横切らなくなるので、木の札の
   まま可読性が出る。**文字に影を重ねて可読性を作らない**――11〜13px
   では滲むだけ（最初それをやって失敗した）。
   ★SVG に入れず CSS の box で持つ。札の SVG は
   `preserveAspectRatio="none"` なので、同じ SVG に置くと角丸と
   削り口の稜線が幅によって寝る。
2. **格を分ける**… 介護度＝ラベル小＋値 19px、相談先＝ラベル小＋
   名前/電話 14px の2行。どちらもラベルを値の上に置くので、値だけを
   拾い読みできる。
3. **彫り込んだ溝**（`.cws-groove`）… 二者の境目。1本のヘアラインだと
   UI の罫に見えるので、**溝の断面**（手前の削り口の陰／溝の底／
   向こう側の削り口が拾う光の3層）を幅 3px で持たせる。

### 格の差の出し方（プレートとの対比）

| | プレート | 木札の帯 |
|---|---|---|
| 厚み | 落ち影 `0 7px 16px` | `0 2px 5px`（板に伏せる） |
| 留め | 真鍮ネジ4本 | ネジ無し・面が接している |
| 面 | 乳白で下地を隠す | 木地のまま |
| 文字 | 白地に載る | 彫り込み（陰＋削り口の光） |

彫り込みの光は**白ではなく木の明部**（`#f7dcb8`）。白にすると札の上に
紙が乗って見える。

### 直し：情報が消えた／主従が逆だった／編集マークだけ浮いていた（同日・レビュー指摘）

彫り込み・格分けまでは直したが、実際にレビューすると3つ問題が残っていた：

1. **Web URL が表示されない**。原因はコードではなく**localStorage の
   古い保存分**。この帯を作る過程で `care.manager` から `state`
   （状態バッジ）を削り `web` を足したが、`hydrate()` の stale 判定に
   この形の変化を入れていなかった。旧セッションの保存分（`web` 無し・
   `state` あり）がそのまま復元され、`web` が undefined になっていた。
   → `staleCare` の判定に「`web` が無い、または `state` を持つ
   `manager`」を追加。**state.js の形を変えるたびに `hydrate()` の
   stale 判定を見直す**――今回のように黙って通ると、直したはずの
   表示が「前のセッションのデータのせいで直っていないように見える」。
2. **名前が主役になっていた**。「山田 花子」を14px太字、
   「○○居宅介護支援事業所」を11.5pxの添え物にしていた。実際に
   電話をかける先・検索する先は法人としての窓口（事業所）で、
   担当者名はその中の「誰か」を添える情報――主従が逆だった。
   → 事業所名を先頭・14px太字に、担当者名は「担当：」を冠した
   添え情報へ。
3. **Web が「サイト」だけの抽象リンクで、電話より一段弱かった**。
   医療の通院カード（`clinics.web`）は `webLabel()` でドメイン名を
   出しているのに、ここだけ固定テキストにしていた。
   → `webLabel(web)` でドメイン名を出し、電話と同じ太さ・近い
   サイズに揃えた。
4. **編集の鉛筆（`.i-secedit`）が帯の中で一番強調された要素だった**。
   既定の見た目（白背景・角丸の枠）はプレートの上で使う前提のもので、
   彫り込んだ薄い文字群の中に置くと**唯一の白い箱**になり、要介護度
   より目立っていた。
   → `.cws-inner > .i-secedit` で白背景・枠線・影を外し、彫り面に
   馴染む単色（`opacity:.55`、hoverで濃く）に落とした。

**この4つは全部、実際にスクリーンショットを見てから分かったもの。**
「彫り込み」「格分け」という造形の骨組みが正しくても、情報の主従・
リンクの読みやすさ・UI要素の強調バランスは別に検討が要る――造形の
正しさと情報設計の正しさは別レイヤーで、どちらか一方をやって
終わりにしない。

## 5. 「今の支援」を2節に割る（2026-09-09・第4回）

「利用している介護・生活支援」の1つの表（4列：種類／事業所／利用状況／
連絡先）を、性質の違う2つに割った。訪問・デイ・配食・生活支援は
**曜日と時間**を持つが、ベッド・歩行器などの福祉用具は**ずっと家に
ある**――同じ表に混ぜると、福祉用具の行にも「利用状況」の欄が要求され、
「常時」のような空疎な記入が並ぶ。

### データの割り方

`SERVICE_KINDS` から `equip`（福祉用具貸与・購入・住宅改修の3制度を
まとめて1つに詰めていたもの）を外し、`care.equipment` を別配列に。
このとき介護保険制度の実態を確認した：

- **貸与（レンタル）・購入（買い切り）** … 家にある物。絵札の対象
- **住宅改修（工事）** … 家にある物ではなく**工事済みの記録**。
  性質が違うので絵札から外した（`papers` 側で扱える）

`EQUIP_KINDS`（bed/walker/monitor/other）と `EQUIP_TYPES`（候補一覧）
を新設。`equipment` も `careRows()` の数え上げに含める（services と
同じ「事業所に連絡できるか」の性質）。

### 造形の判定：ベッドだけ2回崩れて素材探しに切替、また自作に戻った

CLAUDE.md の振り分け（幾何プリミティブ数個で完成するか）に沿って
3種とも自作を試した：

- **歩行器**・**見守り機器** … 1回目の試作で成立（四角い枠＋4本脚／
  壁掛けセンサー＋電波）。「これは何の絵か」を一言で言える。
- **介護ベッド** … 側面図（頭側パネルが斜めに起き上がる表現）で
  2回試して両方とも崩れた（柵が浮いて見える、台車に見える）。
  CLAUDE.md §2 の検出器（2回動かしたら止める）どおり手を止めて
  Openclipart・Wikimedia を探索：
  - [Bed（27650・151933）](https://openclipart.org/detail/27650/bed) …
    ダブルベッド／装飾アンティーク調で、介護ベッドと意味が変わる
  - [Intensive Care（308893）](https://openclipart.org/detail/308893/intensive-care) …
    ベタ塗りシルエットで点滴・モニター・患者まで含む複合絵。
    SeiZen の視覚言語（単色フラット・線＋面取りの2層）と register 不一致
  - Wikimedia `Medical hospital emergency beds.svg` … パブリックドメイン
    だが**赤十字マークを含む地図記号**。国際法上規制されたシンボルで
    一般プロダクトには不適切、除外
  → 3件とも不採用。ユーザー判断（「クオリティを確保できるなら自作で
  問題ない」）に基づき、**向きを変えて**（側面図→真上図）もう一度だけ
  自作。矩形の外枠＋内側マットレス＋頭側/足側の柵（縦棒3本）という
  「正面/俯瞰の記号」の規格に揃えたら1回で成立した。

  **教訓**：2回失敗したのは「向き」（側面図）が悪かったからで、
  「自作かどうか」が悪かったわけではなかった。検出器（2回で止める）は
  正しく機能したが、次の一手は素材探しに固定せず、**同じ絵の別の
  描き方**も選択肢に持つ。実際、他の2枚（歩行器・見守り）が最初から
  正面/俯瞰の記号だったので、規格を合わせる方向へ寄せたのが正着だった。

### 卸しカレンダーの1週分（曜日の帯）

ユーザー明言：「本当に曜日ごとに管理したいというより、デザインとしての
描写目的」。管理項目にはせず、`services` の `use`（自由文）から曜日を
**読み取って**帯に点を打つだけ。`weekdaysOf()` が「月」〜「日」の1文字
一致と「毎日」を拾う。拾えない書き方（「毎日」以外の曖昧な表現）は
空配列＝帯に何も打たない。データは増やさない・DAYS/weekGrid は復活
させない。

**リングは SVG 本体に入れない**。台紙は横に大きく伸びる
（`preserveAspectRatio="none"`）ので、同じ viewBox にリングの円を
置くと引き伸ばしで楕円に潰れ、額縁の桟からはみ出て木目と重なった
（1回目のレンダリングで発覚）。額のダボ（`cbf-peg`）と同じ理屈で、
真円が要る要素は独立した CSS レイヤー（`weekCalendarRings`）に出す。

### プレート内の複数節

「今の支援」は1枚のプレートの中に「暮らしの時間に入る支援」「継続
して使っている支援」の2節を持つ。既存の `carePlate`（プレート1枚＝
節1つ＝鉛筆1つ）の設計に合わないので、`opt.noEdit` でプレート本体の
鉛筆を省き、節ごとに軽い小見出し＋鉛筆（`careSubHead`）を持たせた。
`SEC_OF` に `equipment` を追加（`editSection` は1キーのみ保持する
設計なので、2節が同時に編集状態になることはない＝想定どおり）。

## 6. 3節のブラッシュアップ（2026-09-09・第5回）

前回のレンダリングを正本と並べて、3節それぞれに残っていた問題を直した。
**3つとも造形ではなく「情報の並べ方」の問題**――器（木札・紙・絵札）は
出来ていたが、その中で読む順序と格が立っていなかった。

### ① 相談先｜一続きの文字列になっていた

`事業所名 担当：山田 花子 / 045-… example.or.jp` が横に流れ、
どこからどこまでが何なのか読めなかった。正本（`介護イメージ.png`）の
相談先は **ラベル列＋値列の表**（ケアマネジャー／事業所名／電話番号）で、
値の頭が縦に揃うから3つが別々の情報として拾える。

→ `mgrRow()` でラベル＋値の行を作り、`.cws-mgr-tb` のグリッドに入れた。

**そのあと札が伸びて隣より背が高くなった**（4行積んだ結果）。帯は
「一段軽い格」のはずが、板の上でいちばん重い要素になっていた。
→ 広いときは **事業所＋担当／電話＋Web の2列**に折る
（`repeat(2,auto minmax(0,1fr))`、760px 未満で1列）。札は2行に収まる。

### ② カレンダー｜表に見えていなかった原因は3つとも別

- **リングが紙の外に浮いていた**。`left/right:0` ＋ `space-evenly` だと
  両端のリングが紙の角の丸みの外へ出て、プレートの地の上に乗る。
  → `left/right:5%` ＋ `space-between`（綴じ代の内側に並べる）
- **点が表の中ではなく行の右の余白に見えた**。7列の左端に境目が無く、
  「読む欄」と「曜日の表」が地続きだった。
  → 1列目の左だけ太い罫（`1.5px #d8c9a4`）。表には外枠が要る
- **行が点1つに対して4段の高さだった**。名前／事業所・利用状況／電話を
  3段に積んでいたので、格子が縦に間延びして表に見えない。
  → 電話を `.wcal-meta` に入れて1段に収め、行の padding を 11→8px

加えて曜日の列が右1/3に潰れて左に余白が余っていたので、3列目を
`minmax(168px,268px)` → `minmax(210px,320px)` に広げた。
★`.wcal-head/.wcal-row` と `.wcal-grid` の**2箇所を必ず同じ値**にする
（片方だけ変えると列と点がずれる。CSS 側の既存注記のとおり）。

### ③ 絵札｜「足しただけの札」が実データと同じ格だった

＋で足して名前を書いていない札が、事業所名・電話番号のプレースホルダを
実データと同じ位置・同じ枠で並べていた。結果、空札が「そういう用具が
家にある」ように見える――**正本 §11（空欄と該当なしを同じ扱いにしない）
の違反**が、状態バッジではなく絵札の見た目として出ていた。

→ 名前が空かつ非編集中は「書きかけの札」として、破線の枠・沈めた地・
「未記入の用具」の一行で持つ（`.eqc-blank`）。空のプレースホルダを
3行並べても読むものは無い。

### この回の教訓

第3回で「造形の正しさと情報設計の正しさは別レイヤー」と書いたが、
今回もそのまま当てはまった。**器が出来たあとに1回、実際のデータを
入れて読み直す工程が要る**――リングの貫通・紙の束・彫り込みといった
造形はどれも正しく、崩れていたのは全部その中の並べ方だった。

## 7. 行の中身・支援内容・その場編集（2026-09-09・第6回）

### 同じ失敗を行の中で繰り返していた

§6 ① で相談先の「一続きの文字列」を直したのに、**その同じ回に、行の
meta で同じことをやっていた**――行を低くするために電話を
`.wcal-meta` へ入れ、結果
「○○ケアサービス 月・木 午前（9:00〜12:00頃）045-111-2222」
という切れ目のない文字列を作った（ユーザー指摘）。

**「詰める」は「一列に流す」ではない。** 高さを詰める必要があっても、
性質の違うものを同じ格・同じ段に並べてはいけない。三者を分けた：

| 情報 | 何を答えるか | 置き場所 |
|---|---|---|
| 支援内容（does） | **何を**してもらうか | 名前の次。地の文の濃さ |
| 事業所・電話 | **どこへ**掛けるか | 行の足元。縦罫で区切る |
| 利用状況（use） | **いつ** | 7列の外の4列目 |

区切りは**中黒ではなく縦罫**。中黒は文字列の一部に見えて区切りとして
読めない。

### 支援内容（does）を足した

種類・事業所・曜日だけでは「来て何をする人なのか」が分からない。
家族が代わりに立ち会うときに最初に要る情報で、正本 §13-1 の基準
（必要時に家族が思い出せない・調べられないことか）に当たる。
ケアプランの原本を写すのではなく、一言で分かる粒度で持つ。

**移行は版3→4で「足すだけ」**（`care` を落とさない）。旧い保存分は
`does` が無いだけで他の項目はそのまま使えるので、空文字で埋める。
★§3 の教訓（形を変えたら hydrate/移行を必ず見直す）を今回は先に
適用した――前回はこれを飛ばして「直したはずの表示が直っていない
ように見える」事故を起こしている。

### 利用状況を7列の中に置いてはいけない

最初 `.wcal-when` として曜日の7列と同じ器に縦に積んだら、
「月・木 午前（9:00〜12:00頃）」が**木/金の列の下**に来て、その列の
値のように読めた。点は「どの曜日か」、この欄は「何時ごろか」で、
別の情報――7列の外に自分の列（4列目「時間帯」）を持たせた。

### 編集を下の表からカレンダーの行そのものへ

編集用に `servicesBlock()`（4列の表）をカレンダーの下に出していたが、
**表示と編集で場所が変わり、同じ項目が2箇所に出ていた**（ユーザー
指摘）。行そのものを入力欄にして、旧・表（`serviceRow` /
`servicesBlock` / `.svtbl` / `.svr-*`）は撤去した。型セレクト
（`evServiceKind`）だけは行頭の絵と色を決める機能なので行へ引き継いだ。

**編集中も行の形を保つ**のが肝。最初これを飛ばして入力欄を全幅の箱で
縦に積んだら、1行が表示時の6倍の高さになり、曜日の点が行の遥か上に
取り残された。欄は中身に応じた幅にして、表示のときと同じ場所に置く。
削除の ✕ も、欄の並びの中に素で置くと**空の欄に見える**ので右端へ
寄せた。

### 見出しがチープだった

`今の支援`（白チップ）＋`暮らしの時間に入る支援`（灰色12px）が素の
テキスト2段で、物が何も無かった（ユーザー指摘）。前回「プレート見出し
と格が重ならないよう軽くする」と決めたのが、そのまま「装飾なし」に
なっていた――§3b で木札について通ったのと同じ間違い
（**「軽い」は「装飾なし」ではない**）。

→ プレートは乳白の樹脂板なので、その上に貼られた**インデックス
ラベル**として持つ（紙・左端の色帯・薄い落ち影）。右へ細い罫を渡して
「ここから下がこの節」を示す。
