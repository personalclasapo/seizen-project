# 不動産・物件見出しの造形｜素材探しの記録

物件ごとの記録の各物件（`render.js` の `propHead`）を、屋根のモチーフに
する（2026-09-20）。CLAUDE.md の「自作するか、素材を持ってくるか」に
従い、**自作を2回で止めて素材探しに切り替えた**。その記録。

結論を先に：**使える PD/CC0 素材は見つからなかった。** 自作に戻す。
ただし1回目・2回目と同じ作り方には戻らない（後述）。

## 経緯｜なぜ素材探しに切り替えたか

在来工法の実寸（勾配4/10・軒の出600・破風板180・棟包み120・瓦の働き幅
235・軒樋φ105・基礎立上り400）から引いて、`_検討/不動産v29.html` に
2回描いた。

**1回目の破綻** ―― 瓦の面と破風板を同じ多角形で描いてしまい、屋根が
「180mm の棒」になった。瓦の段はその棒の厚みの中に刻まれて消えた。
原因は座標ではなく**モデルの取り違え**で、妻側から真正面に見ると
屋根の面（瓦）はそもそも見えない。見えるのは破風板・鼻隠し・壁だけ。

**2回目** ―― 視点をわずかに見下ろしに変え、手前の軒先と奥の軒先の
2本で屋根の面を挟んだ。部材（棟包み・破風・軒天・軒樋・基礎）は
層として重なり、瓦の段も乗った。しかし**家には見えない**。

理由ははっきりしていて、積んだ部材が**どれも輪郭線の近くの細部**
だったから。壁が白い面のまま、窓も戸もない。`contract-digital` の
iPhone が成立しているのは、画面という主役の面があってベゼルが脇を
固めるからで、こちらは脇だけ作っていた。

ここで CLAUDE.md の「スクショを見て座標を動かす作業を2回以上やったら
手を止める」に該当したので、素材探しへ切り替えた。

## なぜ「無い」のか

人体シルエット（`body-front.svg`）と違って、**「家の立面」は用途ごとに
形が違いすぎて、汎用の素材が成立しにくい**。存在するのは

- アイコン（家＝三角＋四角の記号。造形の密度が無い）
- 実測図（特定の実在建物。他所の国の、他の様式の家）

の両極で、その中間＝「日本の、ありふれた戸建ての立面」は、
フリー素材として誰も作っていない。商用のストック素材（Dreamstime,
iStock, Vecteezy）には大量にあるが、PD/CC0 ではない。

## ★ 素材は「丸ごと持ってくる」ものではない（2026-09-20 追記）

上の表を「使える素材が無かった」で締めたのは**間違い**だった。
素材探しは「そのまま貼れるものを見つける」作業ではなく、
**素材から描き方を読み取る**作業でもある。

人体（`body-front.svg`）でさえ「丸ごと」ではない――元画像から正面の
1体ぶんのパスだけを抜き、viewBox を正規化し、色は render.js で
上書きしている。素材を**元にした**作業だった。

そして今回、Leicester の実測立面図は手元にある。「英国のテラス
ハウスだから使えない」で切り捨てたが、捨てるべきなのは**その建物**
であって、**その図の描き方**ではない。

### Leicester の立面図から読み取ったこと（実測）

| 読み取り | 数値・内容 | 自作2回目との差 |
|---|---|---|
| **要素数** | パス・線 **385本** | 2回目は約20本。この差が密度そのもの |
| **線の階層** | `stroke-width` が **4 / 2 / 1.5 / 1 / 0.5** の5段。うち **259本が 1**（＝最も細い量産線）、輪郭が 4 | 自作はほぼ全て同じ太さ。階層が無い |
| **壁の埋め方** | 壁面いっぱいにレンガの横目地が**端から端まで**通る。最細線で、テクスチャとして読ませる | **壁を白い面のまま放置していた。これが最大の差** |
| **窓** | ガラスは**黒い面**。白い桟で 3×4 に割る。この黒い塊が正面のリズムを作る | 窓を1つも描いていない |
| **窓まわり** | 3部材（上：アーチ状のまぐさ／周囲：枠／下：水切りの持ち出し＋影の線） | 該当なし |
| **開口の序列** | 上窓 縦横比 **0.92**（ほぼ正方形）、下窓 **1.42**（縦長・大きい）。主室の窓を大きく取り、一様な格子にしない | 該当なし |

**いちばん効くのは「壁の埋め方」。** 最も安い線（最細・等ピッチ・
端から端）を面いっぱいに通すだけで、面が「壁」になる。自作2回は
輪郭の近くの細部（破風・軒樋・棟包み）ばかり積んで、面の中身が
空だった。iPhone が成立するのは画面という主役の面があるからで、
ベゼルだけ作っていた。

**これらは全て様式に依存しない。** ヴィクトリアンだから成立している
のではなく、立面図というものの描き方。日本の戸建てに持ち越せる。

### 何を持ってきて、何を自作するか

- **持ってくる**：上の「描き方」（線の階層・壁の埋め方・窓の作り・
  開口の序列）。パスそのものは持ち込まない
- **自作する**：形。日本の戸建ての窓割りは英国のテラスハウスと違う
  （引違い窓が主、掃き出し窓、玄関の位置、下見板／サイディングの
  横目地）。ここは作るしかない

パスを持ち込まないのは制約からではなく、**持ち込んでも使えない**から。
英国の上げ下げ窓のパスを日本の戸建てに置いても合わない。

### ライセンスについての注記（訂正）

CC BY-SA を「継承義務があるから候補から外す」と書いたが、
**過度に警戒していた**。表示すれば使える。継承義務が及ぶのは
その素材を含む成果物で、プロトタイプは配布物ではない。
CLAUDE.md の「PD/CC0」は推奨であって、BY-SA の禁止とは読めない。

今回パスを持ち込まないのはライセンスの理由ではなく、上に書いた
「持ち込んでも形が合わない」という理由による。**読み取りに
ライセンスは関わらない**（描き方は著作物ではない）。
