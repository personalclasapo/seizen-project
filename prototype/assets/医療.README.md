## 載せないと決めたもの（2026-09-08、ユーザー判断）

正本に §13-1「成果物へ載せるものの基準」を追加し、それに従って
モックから2節を落とした。基準は **「必要になったとき、家族が
思い出せない・調べられないことか」**。

### 普段の状態（左面）

会話・認知・移動・食事の様子は、

- 同居・近居の家族は既に知っている（調べる必要がない）
- 日〜数か月で変わるので、継続更新しないと古い記述が「確認済み」の
  顔で残り、判断を誤らせる（§11の状態は確定しうる事実が前提）
- 更新され続けない情報には、そもそも成立の終点がない（§12）

「普段はこうだから異常ではない」という基準線としての価値は残るが、
それは同席する家族が口で言えるもの。左面に並ぶ「体に合わないもの」
（薬剤名を家族は正確に言えない）とは性質が逆だった。

### 医療で必要になるものと所在（右面）

制度側の固定カテゴリ（診察券・マイナンバーカード・お薬手帳・各種
医療手帳）を並べて所在を埋めさせる作りで、正本 §2 が否定した
「項目を一覧化して埋めてもらう」形そのものだった。加えて4カテゴリ
すべて**既に親がいる**：

| | 本来の持ち主 |
|---|---|
| 診察券 | 通院先（診療案内カード） |
| 機器の手帳 | その機器（左面「体に関わるもの」） |
| お薬手帳 | 「薬を確認するとき」のタイル（`where` として実装済み・重複していた） |
| 保険証・マイナンバーカード | 医療領域固有ではない本人の身分証 |

付随物だけを別の棚に集め直すのは、一度整理したものを二度書かせる
ことになる（§8）。

**所在そのものを否定したのではない。** 通帳・証券・手帳がどこにあるか
分からないのはSeiZenを開く動機そのもので、所在は各対象の側で持つ。
落としたのは「日常的に使っていて家族も知っているもの」の所在と、
それを集めた棚のほう。

（訂正：以前ここに「`SUPPLY_CATS` は未定義で実行時に例外で落ちていた」
と書いたが誤り。実際は state.js に定義・実装済みで正常に動いていた。
撤去の理由は動作不良ではなく、上記の構造上の理由のみ。）

### 番号は持たない

診察券番号のような「現物に印字されている値」は持たない。所在が
分かれば現物へ辿れるのだから、写しを別に持つ意味がない。

## 継続している治療・処置／医療機器・体内機器の欄（2026-09-08）

「医療で必要になるものと所在」を撤去した際、ペースメーカー手帳の
ような付随物は「親（機器）の側に持たせる」方針にした（§13-1）。
これに合わせて、左面「現在の医療状態」の治療・機器フォームを見直した。

**削った欄**

- 「何のため」…機種名からほぼ自動で分かり、独立欄にする価値が薄い。
  書きたければメモへ
- 「頻度・条件」というラベル…治療（インスリン注射等）向けの言い方で、
  常時作動する体内機器には合わない
- 「種類」（体内にあるもの／日常的に使っているもの）…**保存される
  だけで、どこにも参照されないデッドな欄だった。** 人体シルエットの
  塗り分け（塗り＝機器・白抜き＝処置）は devices/treatments という
  項目の違いだけで決まり、この行データを読む先がなかった

**残した・増やした欄**（treatment/deviceで骨は共通、ラベルは性質に
合わせて出し分け）

| 欄 | treatment | device |
|---|---|---|
| 名前 | ◯ | ◯ |
| 続け方 | 継続のしかた（頻度・タイミング） | 使用状況（常時／夜間のみ等） |
| 対応先 | ◯（継続・確認の連絡先） | ✕（かかりつけ経由になり機能しない） |
| 関連するもの | ◯（手帳・カード等の**所在**。存在する場合だけ） | ◯ |
| 体の部位 | ◯ | ◯ |
| メモ | ◯（それ以外の補足） | ◯ |

「関連するもの」は§13-1の所在の扱いをそのまま踏襲：中身（型番等）は
持たず、所在だけを書く欄。

候補チップから足したときも、自由入力で足したときと同じく次に書く欄
（続け方・使用状況）へフォーカスと画面スクロールが飛ぶようにした
（それまでは chip 追加だけ遷移が無く、次に埋める場所が読めなかった）。
