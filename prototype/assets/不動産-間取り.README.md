# 不動産・住まいの造形 ── 間取り図（自作）

不動産領域の成果物UIの造形。`real-estate/render.js` の `PLAN` と
`layout()` が持つ。外部素材は使っていない。

## 何の絵か

**間取り図（平面図）。** 壁を切った断面として見下ろした図に、7つの
項目が部屋として入っている。玄関に表札（基本情報）、右列に「後から
分かりにくい事情」。

## 着手前の振り分け（CLAUDE.md）

CLAUDE.md は「建物」をケース2（＝PD/CC0素材を探すのが先）に挙げて
いる。それでも自作にしたのは、**参考画像のような写実的な建築パースと、
製図記号としての間取り図は別物**だからである。

- 写実パース（参考画像。陰影・植栽・屋根・家具）
  → ケース2。自前のベジェでは破綻する。素材を探すべき側
- 製図の間取り図（壁の二重線・開口・建具の弧）
  → **ケース1。** 矩形と円弧だけで構成され、寸法は実寸比から引ける

採ったのは後者。ユーザー確認済み（2026-09-16、「抽象化した自作の
間取り」を選択）。参考画像は全体のイメージとしての参照で、写実的な
再現は目的にしていない。

### なぜ間取り図のほうが、この領域に合うか

7項目のうち「事情」「権利関係」「関わる相手」は、家の**どの部屋の
話でもない**。写実パースだと家具や部屋の用途が意味を持ってしまい、
「寝室に権利の話がある」ような読み違いを招く。製図の間取り図は
部屋が抽象的な区画なので、項目を割り当てても嘘にならない。

## 寸法の根拠（勘で置かない）

1 SVG 単位 ＝ 10mm。日本の木造住宅の実寸から引いた。

| もの | 実寸 | SVG単位 |
|---|---|---|
| 外壁の厚み | 150mm | 15 |
| 内壁（間仕切り）の厚み | 100mm | 10 |
| 室内ドアの開口 | 780mm | 78 |
| 玄関ドアの開口 | 910mm（半間） | 91 |
| 掃き出し窓 | 1690mm | 169 |

製図の約束として守ったもの：

- **壁は二重線＋45°ハッチ。** 単色の帯にすると間取り図に見えない
- **開口は壁を切って表す。** 壁の上に白い矩形を重ねるのではなく、
  壁の矩形自体を分割する
- **ドアは開口幅を半径とする90°の弧**＋戸の線
- **窓は壁厚の中の三本線**（枠2本＋ガラス1本）
- 方位（N）を右下に置く

## 部屋の寸法は内容から決まる（layout）

**固定寸法にしていない。** 事情が8件ある家では中身が壁を越え、
2件の家では床が余るため、**壁の位置のほうを内容に合わせて動かす**。

`render.js` の `draw()` は2回描く。

1. 見積りの高さで一度描く
2. `measure()` が各部屋の `scrollHeight` を実測し、その寸法で描き直す

見積りの数字をスクリーンショットを見ながら1つずつ詰める作業
（`svg-motif-source-first` の言う人体ループ）に入らないための構造。
ずれたら数字を直すのではなく、測った値を使う。

横方向の割り（x=790 で事情の列、x=430 で上段、x=300 で下段）だけは
内容量ではなく部屋の性格で決めているので固定。

## 狭い画面（≤900px）

間取りをやめ、部屋を縦に積む（`stackOf`）。foreignObject の中身は
画面幅で折り返せないため、造形ごと差し替えている。積む順は事情が先
――この領域の中心だから。造形を保つために内容を読めなくしない。

## 参考画像について

会話で共有された参考画像（写実的な断面パース）は**全体のイメージの
参照**であって、正本ではない。ユーザーより「所々おかしいところは
ある、あくまで全体のイメージ」との指示あり。医療の `医療.png`・
介護の `介護イメージ.png` のような「モックが文章指示に優先する正本」
とは扱いが違う。
